# Локальное тестирование в одной сети Wi-Fi (LAN)

## 1. Архитектура локального стенда

Один компьютер с Windows запускает:
1. PostgreSQL (`127.0.0.1:5432`)
2. Общий Backend + Socket.IO (`HOST=0.0.0.0`, `PORT=8081`)
3. `UzBite Restaurant.exe` (подключается к `http://127.0.0.1:8081` или к LAN IP компьютера)

Мобильные клиенты (телефон покупателя и будущий телефон курьера) подключаются к Backend по **LAN IPv4** компьютера (например `http://192.168.1.100:8081`), **не через `localhost`**.

## 2. Пошаговая настройка на Windows

1. Узнайте локальный IPv4 адрес компьютера:
   ```powershell
   ipconfig
   ```
   Например, `192.168.1.100`.
2. Проверьте корневой `.env`:
   ```env
   NODE_ENV=development
   HOST=0.0.0.0
   PORT=8081
   ALLOWED_ORIGINS=http://localhost:8080,http://127.0.0.1:8080,http://localhost:8082,http://127.0.0.1:8082,http://localhost:8083,http://127.0.0.1:8083,http://192.168.1.100:8080
   ```
   В режиме `development` Backend также разрешает приватные LAN IPv4 origins (`10.*`, `192.168.*`, `172.16–31.*`).
3. Откройте входящие порты `8080` (Vite web, если используется мобильный браузер) и `8081` (Backend API + Socket.IO) в Брандмауэре Windows для частной сети (`Private`).
4. Запустите базу и сервер:
   ```powershell
   npm run db:local
   npm run dev:app
   ```
5. Запустите `UzBite Restaurant.exe` (или `npm run desktop:restaurant`). В окне входа или «Настройки → Подключение к серверу» можно указать `http://127.0.0.1:8081` (если сервер на том же ПК) или `http://192.168.1.100:8081`.
6. На телефоне в той же Wi-Fi сети:
   - Откройте `http://192.168.1.100:8080` (веб-версия) или настройте мобильный клиент на `UZBITE_API_BASE_URL=http://192.168.1.100:8081`.
   - При использовании карты Яндекса на сетевом адресе добавьте `http://192.168.1.100:8080/*` в ограничения HTTP Referer ключа Яндекс Карт.

## 3. Проверка надёжности и переподключения

- При потере сети клиент показывает статус «Нет связи с сервером».
- После восстановления Wi-Fi Socket.IO автоматически переподключается, переподписывается на комнату `restaurant:<id>` и повторно запрашивает актуальное состояние через REST API (`GET /api/restaurant-account/dashboard`, `GET /api/restaurant-account/orders`).
- PostgreSQL остаётся единственным источником истины: повторная отправка запроса на принятие заказа/доставки не создаёт дублей за счёт транзакций `Serializable` и частичных уникальных индексов.
