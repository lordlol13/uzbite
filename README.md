# UzBite (Desktop + Shared API Platform)

Репозиторий desktop-версии и общего сервера UzBite на базе **PostgreSQL + Express + Socket.IO**. Пользовательская витрина (`apps/frontend`) намеренно вынесена за пределы этого репозитория (разрабатывается отдельной командой) и подключается к общему API/БД через документированный контракт ([docs/CLIENT_TEAM_API.md](docs/CLIENT_TEAM_API.md)):

- **Desktop-приложение ресторана для Windows (`apps/restaurant-desktop`, `.exe`)**: полноценный операционный кабинет ресторана с регистрацией/онбордингом `RESTAURANT`, управлением заказами в реальном времени, меню и категориями, импортом/экспортом Excel (`.xlsx`) и CSV (`.csv`), видеопубликациями, двумя режимами доставки (`OWN_COURIER` и `ON_DEMAND_COURIER`), подтверждением оплаты, статистикой, профилем и системными уведомлениями.
- **Desktop-кабинет бизнес-аналитики (`apps/desktop`)**: управленческий отчёт, финмониторинг и расчёт юнит-экономики (`/api/business/*`).
- **Общий Backend + PostgreSQL (`apps/backend`, `prisma`, `packages/shared`)**: обслуживает одновременно desktop-приложения, внешнее клиентское приложение команды (REST `/api/auth/token/*` + Cookies/CSRF + Socket.IO + статические медиа `/images`, `/media`, `/api/media`) и контракт курьера (`/api/courier/*`).

Отправленный покупателем из внешнего клиентского приложения заказ попадает в PostgreSQL в статусе `PENDING_ACCEPTANCE`, мгновенно доставляется в `UzBite Restaurant.exe` по Socket.IO и обрабатывается реальными действиями ресторана и курьеров без имитации таймерами. На карте покупателя никогда не отображается живая GPS-позиция курьера.

## Требования и установка

- Node.js 22.12+; рекомендуемая LTS-версия Node.js 24.
- npm 10+.
- PostgreSQL 17/18.
- Redis для распределённого ограничения запросов; в development без него используется ограничение в памяти процесса. В production недоступность Redis блокирует защищённые этим ограничением действия.
- Для внешних интеграций: браузерный ключ Yandex Maps API 3.0, S3-совместимый bucket и CDN.

Все зависимости устанавливаются из корня. Отдельный `npm install` в `apps/frontend` и `apps/backend` не нужен.

```bash
npm install
```

### Быстрый локальный запуск

Для уже настроенного проекта достаточно одного терминала:

```powershell
cd D:\Projects\Uzbite
npm run dev
```

Команда сначала запускает локальный PostgreSQL, затем Vite и API. Откройте [http://localhost:8080](http://localhost:8080). Для остановки нажмите `Ctrl+C`: приложения завершатся, а база остановится, если её запустила эта команда. Ранее запущенный PostgreSQL продолжит работу. Данные сохраняются в `.local/postgres`.

При первой установке подготовьте окружение и базу:

```bash
npm run setup:local
npm run db:local
```

`setup:local` создаёт игнорируемый `.env` со случайными локальными паролями/JWT-секретами и разрешёнными origins (включая порты для внешнего клиентского приложения), сохраняя существующий файл. Для извлечения предоставленного ключа карты из исходного задания можно передать абсолютный путь в переменной `UZBITE_SPEC_PATH`; значение сохраняется в `apps/restaurant-desktop/.env`.

`db:local` запускает настоящий PostgreSQL на `127.0.0.1:5432`; данные сохраняются в `.local/postgres`. Оставьте этот терминал работающим. На Windows запуск выполняется через штатный `pg_ctl`, который снижает административные права дочернего процесса; отдельная системная служба или пользователь не создаются. Вариант предназначен для разработки и использует пакет embedded-postgres; системная установка PostgreSQL или Docker подходят для постоянной инфраструктуры.

В другом терминале из корня:

```bash
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev:server
```

Backend работает на порту `8081` (`http://127.0.0.1:8081/api/health`). Для запуска только Windows Desktop вместе с сервером в 1 клик используйте [Start-UzBite-Restaurant.cmd](Start-UzBite-Restaurant.cmd).

### PostgreSQL и Redis через Docker

Скопируйте `.env.example` в `.env`, задайте собственные случайные значения `POSTGRES_PASSWORD`, `JWT_SECRET`, `JWT_REFRESH_SECRET`. В `DATABASE_URL` укажите тот же пароль, URL-кодировав специальные символы.

```bash
docker compose up -d
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev:api
```

Не запускайте Docker PostgreSQL и `db:local` одновременно на одном порту. Docker-сервисы привязаны к loopback; наружу публикуется только Vite. Вместо Docker можно создать БД `uzbite` и отдельного пользователя в системном PostgreSQL, затем настроить `DATABASE_URL`. Redis настраивается через `REDIS_URL`.

На Windows перед повторной генерацией Prisma Client остановите API: загруженная native DLL может быть заблокирована процессом Node. Обычная сборка не перегенерирует Client; после изменения схемы отдельно выполните `npm run db:generate`.

Интеграционные тесты создают собственные временные аккаунты и проверяют серверное хранение. Запускайте их на отдельной development/test БД. Применение частичного уникального индекса обязательно: один активный заказ обеспечивается PostgreSQL даже при параллельных запросах. `db push` не заменяет миграции, поскольку не создаёт этот индекс.

## Архитектура

```text
apps/restaurant-desktop/   Electron + React + Vite Windows .exe кабинет ресторана (15 экранов, 8083/18083)
apps/desktop/              Desktop-кабинет бизнес-аналитики и финконтроля
apps/backend/              Express, Prisma, JWT/Cookies+Bearer, Redis, Socket.IO, ExcelJS, S3/local media + public/
packages/shared/           Общие JSON-контракты, DTO и статусы
prisma/                    Нормализованная схема, SQL-миграции, идемпотентный seed
scripts/                   Настройка локального окружения, PostgreSQL и серверный launcher
tests/                     Интеграционные сценарии (внешний клиент, аналитика, ресторан, курьеры)
docs/                      Спецификация, API для команды клиентской части, доставка, Excel/CSV, LAN и деплой
```

Одна корневая установка npm workspaces и один `package-lock.json`. Цены хранятся как PostgreSQL `Decimal`; сервер рассчитывает сумму из актуального меню и сохраняет снимки заказа. В API суммы передаются числами для отображения. Цены, роли, принадлежность адресов, оплаченный статус и статус доставки не принимаются на доверии от клиента.

Авторизация использует короткий access JWT и обновляемую серверную сессию с хешированным refresh nonce. Cookie с токенами имеют HttpOnly и SameSite; в production также Secure. Изменяющие запросы требуют CSRF-токен. Публичная регистрация принимает только пользовательские поля, дополнительные роли отклоняются. Пароли хешируются bcrypt. После смены пароля сессии отзываются.

## Карта и локальная сеть

Время доставки в поиске пересчитывается для выбранного адреса аккаунта. Формула: время приготовления ресторана + передача курьеру + расстояние по координатам × коэффициент дорог / средняя скорость. Показан примерный диапазон с округлением до 5 минут. Live-пробки и дорожная маршрутизация не подключены. Поле `Restaurant.preparationMinutes` задаёт приготовление (по умолчанию 20 минут); скорость, коэффициент дорог, передача и запас настраиваются через `DELIVERY_*` из `.env.example`. Адрес сохраняется в аккаунте, используется в оформлении и обновляется после заказа; у существующих аккаунтов подставляется адрес прошлого заказа либо основной сохранённый.

Клиент читает `VITE_YANDEX_MAPS_API_KEY` из `apps/frontend/.env`. Пример этого файла не содержит реального ключа. Используется официальный JavaScript API 3.0, ожидание `ymaps3.ready` и порядок `[longitude, latitude]`. Внутренняя модель сохраняет именованные поля `longitude`, `latitude`.

Карта нужна для выбора точки доставки. Текст адреса вводится пользователем; приложение не предполагает наличие отдельной лицензии Геокодера и не генерирует адрес по координатам. Для production нужно отдельно подтвердить право долговременного хранения выбранных координат и иных данных по тарифу/договору Яндекса. Политика хранения результатов геокодирования не применяется к выдуманным данным: такие данные приложение не создаёт.

Для доступа с телефона:

1. Узнайте локальный IPv4 компьютера командой `ipconfig`.
2. Включите разрешённый origin `http://<IPv4>:8080` в `ALLOWED_ORIGINS`, перезапустите API.
3. Разрешите входящие соединения TCP 8080 в Windows Firewall для частной сети.
4. Подключите телефон к той же сети и откройте `http://<IPv4>:8080`.
5. Добавьте этот источник в ограничения HTTP Referer ключа Яндекса. Разрешение `localhost` не разрешает сетевой IP автоматически.

Vite слушает `0.0.0.0:8080` со `strictPort: true` и проксирует `/api` и `/socket.io` на 8081, включая WebSocket. Клиент использует относительные пути. Занятый порт 8080 приводит к ошибке, а не к скрытой смене адреса.

Геолокация браузера доступна на localhost как доверенном адресе; на обычном LAN HTTP-адресе телефон может отказать из-за отсутствия HTTPS. Выбор точки вручную должен оставаться доступным. Ошибка ключа, сети или Referer показывается в интерфейсе с повторной загрузкой. Кнопка «Карта» у ресторана открывает его сохранённые координаты во внешних Яндекс Картах; отдельного режима поиска организаций и трекера курьера нет.

## Медиа и оплата

Seed содержит 6 вымышленных ресторанов, 18 блюд, стоковые изображения и 2 настоящих food-видеоролика. Два HD-ролика включены в `apps/frontend/public/media` и отдаются локально; первая публикация — вертикальное видео приготовления пасты. Источники и лицензии перечислены в [docs/MEDIA_SOURCES.md](docs/MEDIA_SOURCES.md). Нельзя считать эти рестораны реальными партнёрами или принимать их демонстрационные точки за подтверждённые адреса бизнеса.

Для аватаров и чеков настройте `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_PRIVATE_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `CDN_BASE_URL`. Не используйте публичную политику доступа на весь bucket. Аватары могут доставляться через CDN из `S3_BUCKET`, чеки должны оставаться в отдельном приватном `S3_PRIVATE_BUCKET` и выдаваться только владельцу через короткие подписанные ссылки. Метаданные хранятся в PostgreSQL. При отсутствии конфигурации сервер возвращает понятную ошибку, не изображая успешную загрузку.

Наличные поддерживаются без чека. Карточная оплата доступна только при реальных реквизитах/QR ресторана и подключённом хранилище чеков. Seed намеренно не содержит выдуманных платёжных данных. Прикрепление чека создаёт статус «Ожидает подтверждения», не «Оплачено». Подтверждение рестораном и реальное списание с карты в текущий этап не входят. Карточные номера/CVV приложение не собирает.

## Проверка и production

Проверяйте `/api/health` через 8080 и напрямую через 8081. Подключение Socket.IO требует авторизованной cookie-сессии; при переподключении клиент заново запрашивает актуальные данные API. Смена статуса для проверки выполняется только локальной developer-командой. Пользовательский API не позволяет менять статусы, подтверждать оплату или присоединяться к чужому заказу.

Перед production задайте `NODE_ENV=production`, HTTPS reverse proxy, корректные origins, сильные отдельные JWT-секреты, PostgreSQL и Redis, объектное хранилище и права ключа карты. Соберите проект `npm run build`; отдавайте `apps/frontend/dist` со SPA fallback на `index.html`, проксируя `/api` и `/socket.io` к API. Запуск compiled backend выполняется из его workspace командой `npm run start -w @uzbite/backend`. Секреты и содержимое `.local` не включаются в исходники.

Фактические результаты проверок и ограничения находятся в [docs/PROJECT_STATUS.md](docs/PROJECT_STATUS.md); история — в [docs/CHANGELOG.md](docs/CHANGELOG.md). Подробная документация по модулям и интеграции:

- [docs/DELIVERY_WORKFLOWS.md](docs/DELIVERY_WORKFLOWS.md) — два режима доставки (`OWN_COURIER` и `ON_DEMAND_COURIER`), разделение `OrderStatus` / `DeliveryStatus`
- [docs/COURIER_API_CONTRACT.md](docs/COURIER_API_CONTRACT.md) — REST/Socket.IO контракт `/api/courier/*`

Юридические тексты в интерфейсе являются проектами и требуют отдельного согласования перед публичным запуском.


Светлая тема использует чистый белый фон #FFFFFF. Корзина хранится отдельно для каждого аккаунта; язык регистрации и локализованные уведомления сохраняются в профиле. Списки заказов, лайков, подписок, комментариев и уведомлений поддерживают пагинацию. Мобильный выбор адреса открывается на весь экран; сохранённый адрес можно редактировать прямо из оформления.
